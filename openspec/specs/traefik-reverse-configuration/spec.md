# traefik-reverse-configuration Specification

## Purpose

Provides safe, review-only inspection and reconstruction candidates for Traefik configuration while acknowledging that provider-generated runtime state is not always fully declarative or representable.

## Requirements

### Requirement: Traefik observation distinguishes configured and provider-generated state
The system SHALL observe the effective supported static and dynamic configuration, declared files/options, entrypoints, routers, services, middlewares, TLS metadata, and provider-generated runtime objects that can be queried safely. Observations SHALL include deterministic ordering, source/provider provenance, ownership, supported fields, unsupported findings, and completeness without mutating Traefik, configuration files, runtime secrets, or persistence state.

#### Scenario: File-backed configuration is observed
- **WHEN** Traefik loads a static file and a file-provider dynamic configuration
- **THEN** observation reports the representable configuration with its source provenance and does not modify either file or the running service

#### Scenario: Provider-generated state is identified
- **WHEN** a router or service is generated by Docker, Kubernetes, Consul, or another provider outside the declared file configuration
- **THEN** observation identifies the external provider and does not claim that the state can be reproduced by the file-backed candidate alone

### Requirement: Drift conversion is review-only and secret-safe
The system SHALL provide drift detection and candidate conversion for supported changes to Osmium-managed Traefik configuration. Candidates SHALL exclude ACME private keys, DNS/API credentials, TLS private keys, environment-file values, and other runtime secrets; preserve unresolved file and secret references; identify provider-generated or unsupported state; and mark the candidate incomplete and not activation-ready when required state cannot be represented.

#### Scenario: Managed router drift produces a candidate
- **WHEN** a supported managed router or middleware changes in the running Traefik configuration
- **THEN** drift conversion derives a review-only candidate from runtime observation, identifies the changed resource and provenance, and leaves the active service and source files unchanged

### Requirement: Live capture is derived from runtime observation
The system SHALL provide a live-capture conversion that reads effective Traefik runtime/configuration state from a running service and produces a reviewable candidate rather than an independently authored equivalent fixture. Capture SHALL report missing entrypoint definitions, provider credentials, dynamic file paths, generated certificates, or unsupported provider state as explicit incompleteness.

#### Scenario: Live configuration is captured
- **WHEN** an operator creates a route through a supported file provider and an externally generated provider route in a source MicroVM
- **THEN** live capture includes the file-provider route, records the external provider route as unresolved or unsupported, excludes secret values, and does not mutate the source

### Requirement: Reverse configuration is exercised in dedicated MicroVM checks
The system SHALL expose separate checks named `traefik-drift-reverse-configuration` and `traefik-live-capture-reverse-configuration`. Each check SHALL boot a source MicroVM, derive conversion output from runtime observation, prove source non-mutation, and boot or validate a replay configuration that reproduces all complete represented routing behavior while reporting exact blockers for incomplete state.

#### Scenario: Drift reverse-configuration check executes
- **WHEN** `nix build .#checks.x86_64-linux.traefik-drift-reverse-configuration --print-build-logs` runs
- **THEN** it boots a source MicroVM, creates supported runtime drift, derives the candidate from observation, proves non-mutation, and validates replay or explicit incompleteness

#### Scenario: Live-capture reverse-configuration check executes
- **WHEN** `nix build .#checks.x86_64-linux.traefik-live-capture-reverse-configuration --print-build-logs` runs
- **THEN** it boots a source MicroVM, captures runtime-created configuration, proves the candidate is runtime-derived and secret-safe, and validates replay or explicit incompleteness
